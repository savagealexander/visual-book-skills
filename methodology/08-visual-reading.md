# 图文联合阅读（按内容需要启用）

适用于正文依赖图表、流程图、几何图、公式图、标注截图等证据的来源。
文字书沿用原流程。这里约束阅读和证据交付，不提升底层模型视觉能力，也不代替实际评测。

## 1. 阶段 0：建立图文范围

- 从目录、图目录、正文的图号引用和页面预览定位候选图页。抽样仅用于判断内容类型；
  不把抽样说成全书已读。登记所选范围内的全部关键图号、PDF 页序、对应解释所在页。
- PDF 页序从 1 开始；封面、前言会导致它不同于书本页码。书本页码未看清就留空，
  不通过统一偏移猜测。跨页解释与多个子图分别登记。
- 先渲染完整页面再看局部：PDF 图形可能由矢量线条、文字和图片共同组成，
  单独导出嵌入图片可能遗漏关键结构。扫描页也要看图，OCR 文本只能作辅助。

先运行 `python3 scripts/cangjie.py doctor`。图像模式需要 Pillow 与 Poppler
（`pdfinfo`、`pdftoppm` 在 PATH）；文本模式不增加这些依赖。
页内文字优先用 `pdftotext`，也可安装 `pypdf` 作为后备；两者都没有时仍可渲染，
但清单标为 `text_status: unavailable`，需要另行取得正文，不能把它当成无文字页面。

```bash
python3 scripts/cangjie.py render-pages --pdf "/path/book.pdf" \
  --pages 18-20 --source-id src-book \
  --out "/path/work/book-pages-18-20"
```

`--pages` 是 PDF 页序。默认长边 3200 像素，可用 `--max-edge 4800` 提高细节。
单页需要局部图时加 `--crop 0.08,0.12,0.94,0.70`（相对完整页面左上角的归一化
x0,y0,x1,y1）；完整图始终保留。不要猜坐标：先打开页面确定图表范围。
输出目录必须是新目录，以免覆盖旧版本的核查记录。

产出包括完整 PNG、可选局部 PNG、该页的文本层和 `manifest.json`。
清单保留来源 SHA256、PDF 页序、图片哈希、尺寸与裁切位置，不记录源文件绝对路径。
空文本不代表空白页面；脚本不做 OCR、图号识别或语义判断，初始状态总是 `unreviewed`。
其他格式用宿主可用的渲染工具，但同样保留来源、完整图、正文和定位。

## 2. 阶段 1 / 1.5：真正看图并核对正文

使用宿主图像查看工具实际打开完整图和必要的局部图；仅看到路径、OCR 或图注不算看过。
读取图注及解释该图的前后文。用 `templates/FIGURE_EVIDENCE.md.template` 建立记录：

- **可见事实**：坐标轴/单位、图例、线条、编号、箭头、子图、相对位置和可辨认数值。
- **作者解释**：定位到具体正文段落，逐条对应图中对象，保留前提与例外。
- **推断**：模型从图文得出的判断，标记为推断，不能写成作者结论或精确测量。
- **缺口/冲突**：遮挡、模糊、裁切丢失上下文、正文与图号不一致；关键缺口进入
  `needs-review.md`，解决前不作为 active 能力的依据。

看不清时重新放大/渲染，仍不清就标未知。没有比例尺或 OHLC 数据时，不从像素
猜精确价格、收益率或概率。对图形状态的确定性不高时记录可支持的解释和反对证据。
章节核查时对照图目录/正文引用和清单，报告已读、待核查、未覆盖数量与具体范围。

### Brooks / 时序图表的附加要求

- 放大局部 K 线时保留完整走势背景，逐一核对作者引用的 K 线编号、箭头及方向。
- 区分书中的案例解释与可推广的条件规则；不能从一次成功案例推导胜率。
- 区分“复盘已发生走势”和“站在当时判断”。后者只提供截至指定 K 线的数据，
  隐藏右侧走势及透露答案的标题/标注，保留原始完整图用于事后核查。
- 编译时在该能力的 E/B 中写入这些输入限制和判停条件，不能只留在生成过程里。

## 3. 阶段 2 / 5：交付可回查的证据

只把该能力实际依赖的图、局部图和核查记录复制到 Bundle 的 `resources/figures/`。
避免把整本书的文本层/全部书页作为默认资源。每个文件在 `resources` 中显式声明，
用不同来源/版本的子目录避免重名；原始准备清单留在本地审计目录。
核查记录的图片链接应相对记录本身，例如 `page-0018.png`，不能指向准备目录的绝对路径。

在能力元数据添加：

```yaml
resources:
  - resources/figures/example/page-0018.png
  - resources/figures/example/page-0018-detail.png
  - resources/figures/example/figure-notes.md
visual_evidence:
  - figure_id: fig-example
    source_id: src-book
    source_sha256: "<从 manifest.json 复制真实的 64 位 SHA256>"
    pdf_page: 18
    printed_page: null
    image: resources/figures/example/page-0018.png
    detail_image: resources/figures/example/page-0018-detail.png
    notes: resources/figures/example/figure-notes.md
    review_status: reviewed
```

`reviewed` 只在完成实际看图、正文核查和记录后写入；有关键缺口用 `needs_review`，
对应候选不进入 active 能力池。现有 `source_evidence` 同时保留正文出处。
编译器检查声明、文件存在、图片可解码及状态，并生成适配 single/router/promoted 的相对链接。
这些机械检查不核实语义，不能以“编译成功”报告“读图准确”。

支持静态 PNG/JPEG/WebP，单张最多 25 MiB、40MP；图片分支需要 Pillow。
文本资源保持兼容。图片纳入发布哈希、手改检测、快照和回滚。
后续原图/版本/裁切变更时，重新核查依赖它的能力并更新来源哈希；不要沿用旧 reviewed。
当前 `update --add` 仍仅处理文本，图片变更需要在 Bundle 更新后重新 compile 并回归测试。
安装时复制完整 Skill 目录。分享前遵守原始材料的授权范围；私人书页不随工具代码发布。

## 4. 阶段 4：评测图文能力

分开报告三项：资源完整性、原书图文理解、新图任务应用。
保留同一模型/工具/预算下的“原版/改进版/无 Skill”对比，使用未参与生成的新图验收。

最低覆盖：完整图正常阅读、需要局部放大、图文编号对应、模糊/缺图判停、
外形相似但前提不满足的反例、时序任务的未来信息隐藏。
同一原图的不同裁切属于同一组，不能跨训练/验收集合；按图或来源分组留出。
评测执行者看不到图注答案/预期结论，评审者再用原文核查。记录图片工具是否真正调用、
原图是否可读、结论的依据及缺口；没有实际运行数据就只报告基础设施验证。
